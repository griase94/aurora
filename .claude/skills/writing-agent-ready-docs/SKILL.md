# Writing agent-ready docs

Agents read Aurora through text files, not through the Storybook single-page app (an empty
shell without JavaScript). Every agent file is generated by `kit:gen`
(`apps/docs/scripts/kit-gen.ts`, emitters in `kit-index.ts`) from source: the component, its
JSDoc, its `parameters.kit`, its stories, its example file and `packages/*/package.json`.
Never hand-edit a generated file; fix the source or the generator.

## The files

| File                         | What it holds                                                         |
| ---------------------------- | --------------------------------------------------------------------- |
| `llms.txt`                   | llmstxt.org index: H1, `>` summary, rules, install section, then `## Start`, `## Foundations` and one `## <Family>` list per family of `- [Name](…/c/<slug>.md) purpose \`import\` [docs](…)` |
| `c/<slug>.md`                | one component in plain Markdown: purpose, when to use, variants, anatomy, example, do and don't, parts, props, tokens |
| `p/<slug>.md`                | the Markdown twin of a Start or Foundations page                      |
| `kit.json`                   | the same facts as JSON (`schemaVersion`, `package`, `pages`, `components`, `tokens`, `charter`) |
| `llms-full.txt`              | every page's prose in one file                                        |
| `packages/svelte/AGENTS.md`  | install, import, styles, charter summary; shipped in the package      |

`kit:gen` writes them to `apps/docs/src/lib/kit/generated/public/`; the Handbook serves them
at `/handbook/`, and `site-compose.ts` copies `llms.txt`, `llms-full.txt` and `kit.json` to
the site root, where llmstxt.org says an agent looks.

## Rules

- **Derive every package fact.** Names, aliases, version, entries, CSS entry, theme and brand
  attributes come from `packages/*/package.json` and the entry table through
  `apps/docs/scripts/kit-package.ts`. Never type a package name or scope into prose, MDX or a
  generator: a scope rename must stay a one-line change.
- **API-dense, not narrative.** Facts, one runnable example, rules with reasons. No repository
  tour, no history, no maintainer notes: research on context files found that overviews do
  not help agents and specific instructions do.
- **One example per component, written as a consumer writes it**:
  `apps/docs/examples/<slug>.svelte`, importing only public package entries (`<package>/<entry>`),
  no `$lib`, no `$kit`, no relative path. `kit:gen` prints it verbatim into `c/<slug>.md` and
  `kit.json`; `pnpm -C apps/docs examples:check` type-checks it.
- **Props come from the component.** Name, type, default resolved to its value (`"md"`, not a
  constant's name), the JSDoc sentence, allowed values from the variant table. A prop the
  component destructures with a default or `$bindable()` must appear in the props table.
- **Do and don't come from the stories' `<DoDont>`** (`good`/`bad` snippets with `goodWhy` and
  `badWhy`), read by Svelte's parser in `kit-examples.ts`, never retyped.
- **Aurora's rules only.** `AGENT_RULES` in `kit-index.ts` states what holds for every app
  that uses Aurora. A consuming app's own conventions belong in that app's `AGENTS.md`.
- **The public build (`KIT_PUBLIC=1`) publishes public facts only:** no Studio knobs
  (`@studio`), no file paths of an app, no maintainer notes, status in the public words
  Stable, Beta, Deprecated.
- **Every link resolves in the composed site.** `check-site.ts` reads the built site and fails
  on a `llms.txt` link that names no file of the build.
- **`kit.json` keeps `schemaVersion: 1`** while fields are only added; renaming or removing a
  field bumps it.

## The readiness gate

`pnpm -C apps/docs llm:check` regenerates the public files into a temporary folder and asks
the question an agent has: starting from `llms.txt`, can it find a component, import it and
use three of its props correctly? It parses each `c/<slug>.md` (props tables, the example
fence, every import) and holds it against `kit.json`. What is still open is a line in
`apps/docs/scripts/llm-readiness.allowlist.txt` (`<slug> <rule>: <reason>`); a line whose
problem is gone fails the run, so the list only shrinks. Never add a line to get green; add
the missing fact.

## Choices already made

- **No Storybook MCP docs toolset yet.** It needs Storybook's component manifest, which this
  Storybook version does not generate for Svelte. The public contract is the files above.
- **No `Accept: text/markdown` negotiation:** the site is static. Explicit `.md` URLs plus a
  `rel="alternate"` link in each site head are the baseline.
- `llms.txt` is a proposal, not a standard, and `llms-full.txt` is a convention outside it.
  Judge them by what an agent can do with them (the gate), not by crawler traffic.

## Check your work

```sh
pnpm -C apps/docs kit:gen
pnpm -C apps/docs llm:check                 # exit 0: every component passes or is allowlisted
pnpm -C apps/docs examples:check            # the example files type-check
pnpm test:fast tests/unit/kit-llm-readiness.test.ts tests/unit/kit-index.test.ts \
  tests/unit/kit-llm-emitters.test.ts tests/unit/kit-gen-public.test.ts
# No hard-coded published name outside package.json (prints nothing):
for p in packages/*/package.json; do n=$(node -p "require('./$p').name"); git grep -nF "$n" -- apps/docs/src apps/docs/scripts '*.mdx'; done
```

Then the agent test: give a fresh agent only `llms.txt` and a task such as "add a
confirmation for a destructive action to a new SvelteKit page". It must install the right
packages, import from a public entry, pass only declared props and pick the component the
"Choose a component" table names, without opening the Storybook UI. A miss is a missing
fact: fix the generator or the source, then add the case to the readiness rules.
